#+TITLE: dotfiles

Configuration personnelle : zsh, Neovim, WezTerm, outils CLI et assistants IA
(Claude Code, opencode). Déployée avec [[https://www.gnu.org/software/stow/][GNU Stow]].

* Installation

** Linux / WSL — une commande

#+begin_src sh
bash <(curl -fsSL https://raw.githubusercontent.com/adrnbttr/dotfiles/master/script/get)
#+end_src

Clone le dépôt dans =~/Documents/github/perso/dotfiles=, installe les outils,
puis crée les liens symboliques. Compter 5 à 15 minutes selon la connexion.

Prérequis : Debian/Ubuntu (apt), un compte avec =sudo=, un accès Internet et
~2 Go libres. Le script les vérifie avant de commencer et s'arrête net s'il
manque quelque chose.

** Windows — une commande

#+begin_src powershell
irm https://raw.githubusercontent.com/adrnbttr/dotfiles/master/script/get.ps1 | iex
#+end_src

Installe WezTerm et la police MesloLGS NF, met en place WSL + Ubuntu si besoin,
puis lance l'installation Linux *dans WSL*, pointe WezTerm sur la config
(=~\.wezterm.lua=) et ajoute =Documents\github= dans l'Explorateur.
Prérequis : Windows 10/11 avec winget (« App Installer » du Microsoft Store) ;
PowerShell en administrateur si WSL n'est pas encore installé. Si WSL vient
d'être activé, redémarrer puis relancer la même commande.

** macOS

#+begin_src sh
bash <(curl -fsSL https://raw.githubusercontent.com/adrnbttr/dotfiles/master/script/get)
#+end_src

Prérequis : [[https://brew.sh][Homebrew]] et les outils de développement (=xcode-select --install=).

** Vérifier et réparer

#+begin_src sh
./script/doctor        # ce qui est en place, ce qui manque
./script/doctor --fix  # relance uniquement les étapes manquantes
#+end_src

** Options

#+begin_src sh
./script/install --list              # liste les étapes
./script/install --dry-run           # montre ce qui serait fait, sans rien installer
./script/install --only "wezterm"    # rejoue une étape précise
./script/install --skip "claude"     # saute une étape
./script/install --minimal           # outils CLI de base seulement
./script/install --no-gui            # sans les terminaux (kitty, wezterm)
#+end_src

Chaque étape est isolée : si l'une échoue, les autres continuent et le résumé
final indique quoi rejouer. Le détail complet part dans
=~/.local/state/dotfiles/<date>.log=.

** Mettre à jour

#+begin_src sh
cd ~/Documents/github/perso/dotfiles && git pull && ./script/install
#+end_src

* Features / memo

** Zsh

- Custom theme lives in =$ZSH_CUSTOM= (default: =~/.config/oh-my-zsh=), so =omz update= works.
- Optional extras installed by `./script/bootstrap`:
  - zsh-autosuggestions
  - fast-syntax-highlighting
  - fzf-tab
- History is shared across shells and stored under XDG state (default: =~/.local/state/zsh/history=).

Quick examples:

# Run dotfiles health checks

Keyboard hints:
- autosuggestions: accept suggestion with Right Arrow
- fzf-tab: use TAB completion then pick in the fzf UI

Terminal tip:
- Ctrl-S is enabled for Neovim/Kitty (XON/XOFF disabled via `stty -ixon` in `zsh/.zshrc`).

** WezTerm (Linux + Windows)

Config: `config/.config/wezterm/wezterm.lua` (même fichier pour Linux et Windows).
Installé par `./script/install` (Linux, dépôt apt officiel + terminfo `wezterm`)
et par `script/get.ps1` côté Windows (cf. Installation).

Sous Windows, WezTerm ouvre la distribution WSL (Ubuntu en priorité) : lancer
ensuite `./script/install` dans WSL pour zsh, nvim et les sessions.

Windows en pratique :
- WezTerm lit =%USERPROFILE%\.wezterm.lua=, écrit par `script/get.ps1`, qui
  charge `wezterm.lua` depuis le clone WSL (=\\wsl$\Ubuntu\...=). Si WezTerm
  était déjà ouvert pendant l'installation, le fermer puis le rouvrir.
- Les dépôts vivent dans WSL, sous =~/Documents/github/perso= (git et nvim y
  sont bien plus rapides que sur =/mnt/c=). Depuis l'Explorateur :
  =Documents\github= (raccourci créé par `get.ps1`). Cloner un dépôt là, puis
  `github-session` ouvre un onglet nvim par dépôt dans le workspace =github=.
- zsh doit être le shell par défaut de WSL (étape `shell` de `./script/install`) :
  c'est lui que WezTerm lance, et les sessions sont des fonctions zsh.
- git dans WSL (étape `git`, sans effet hors WSL) : reprend l'identité de git
  Windows et s'authentifie sur GitHub via le =gh.exe= Windows déjà connecté,
  pour cloner, pull et push les dépôts privés sans clé ni jeton dans WSL.
- Police : 8.25 sous Windows (écran à 125 %), 11 sous Linux.

*Clavier BÉPO sur un portable AZERTY (Windows)* : `windows/clavier/` pose les
lettres en BÉPO tout en gardant les caractères spéciaux imprimés sur les touches
(ThinkPad belge). Une commande dans PowerShell, AutoHotkey installé au passage :

#+begin_src powershell
irm https://raw.githubusercontent.com/adrnbttr/dotfiles/master/windows/clavier/get.ps1 | iex
#+end_src

Détails et tableau des touches : `windows/clavier/README.md`.

Dispositions clavier : les raccourcis suivent le *caractère* produit (Ctrl+Alt+z
reste sur la touche « z » en BÉPO comme en AZERTY) et Alt+1…9 les touches
*physiques* du haut (pas de Shift). Seules les lettres de Ctrl+Alt+a / x
s'adaptent à la disposition, détectée via `setxkbmap` (AZERTY par défaut sous
Windows) ; écrire `bepo`, `azerty` ou `qwerty` dans `~/.config/wezterm/keyboard`
force le choix.

Différences sous Windows (le même `wezterm.lua`, branche `IS_WINDOWS`) :
- Ctrl+Alt+lettre devient Ctrl+Alt+Shift+lettre (AltGr arrive comme Ctrl+Alt).
- Sélecteurs `ctrl+shift+s` / `ctrl+shift+o` : version native de WezTerm
  (fzf et `wez-pick` vivent dans WSL) ; pas de ctrl+x / ctrl+r ni de reprise
  au démarrage. Le marquage jaune des workspaces qui sonnent fonctionne.
- Pas de `TERM=wezterm` (terminfo absent côté WSL) ni de domaine Unix.
- F1 lit `~/.config/wezterm/cheatsheet.txt` **dans WSL** (le chemin Windows de
  la config n'y est pas lisible).
- La confirmation avant fermeture reste active : fermer tue les onglets.

Pas de sessions persistantes : le mode connecté à `wezterm-mux-server` rate
les redimensionnements avec beaucoup d'onglets nvim (voir `wezterm.lua`).

Workspaces : `de-session`, `ms-session`, `github-session` et
`marvin-session` ouvrent chacune leur workspace (de, ms, github, marvin) ;
les relancer n'ajoute que les onglets manquants. Elles sont déclarées dans
`config/.config/wezterm/sessions.conf` (nom du workspace + commande), lu par
le sélecteur `wez-pick`.

Au démarrage, WezTerm propose de reprendre les workspaces de la fois
précédente (mémorisés dans `~/.local/state/wezterm/workspaces`) ; Échap ouvre
un shell simple. Quand un programme sonne (Claude Code en attente) dans un
workspace qu'on ne regarde pas, son nom passe en jaune dans la barre et il est
marqué dans le sélecteur.

Bureaux Cinnamon déplacés sur Super+Ctrl(+Shift)+flèches par `./script/install`,
pour laisser Ctrl+Alt(+Shift)+flèches au terminal.

** Neovim

- This repo commits `config/.config/nvim/lazy-lock.json` so plugin versions are reproducible across machines.
- By default, `./script/bootstrap` will *not* overwrite an existing =~/.config/nvim/lazy-lock.json=.
- Recent edits are briefly highlighted (10s) so you can spot changes from tools like opencode.
- File explorer (LazyVim / neo-tree) opens by default on startup (disable with `NVIM_NO_EXPLORER=1`).

Use the repo lockfile on a machine that already has a local one:

#+begin_src sh
mv ~/.config/nvim/lazy-lock.json ~/.config/nvim/lazy-lock.json.bak
./script/bootstrap
#+end_src

** AI Coding Assistants

This dotfiles supports two AI coding assistants running in parallel:

1. **OpenCode** (primary) - For general coding tasks
2. **Claude Code** (secondary) - For complex reasoning with Claude 4.6 Sonnet

They are independent tools — OpenCode runs a local server, Claude Code is a direct CLI authenticated via browser (Claude Pro/Max subscription).

*** opencode

This repo ships a small, safe subset of opencode state as *templates*:
- UI preferences: `opencode-state/.local/state/opencode/kv.json`
- Recent models: `opencode-state/.local/state/opencode/model.json` (deepseek, GPT-5)
- System prompt: `opencode-state/.local/state/opencode/system_prompt.md`
- Configuration: `opencode-state/.config/opencode/opencode.json`
- TUI settings: `opencode-state/.config/opencode/tui.json`
- Environment optimizations: `opencode-state/.config/opencode/env.sh`

*** Claude Code

Claude Code stores sessions under =~/.claude/= (managed by the CLI itself).
This repo tracks only:
- Global system prompt: =claude-state/CLAUDE.md= → deployed to =~/.claude/CLAUDE.md=
- Settings: =claude-state/settings.json= → deployed to =~/.claude.json=

Auth is browser-based — no API key needed (requires Claude Pro/Max subscription):

#+begin_src sh
claude --login
#+end_src

*** Shared Resources

- Prompts templates: `shared-prompts/` (code-review, documentation, etc.)
- Shell aliases: `zsh/.zshrc.d/{opencode,claude}.zsh`

Both intentionally do *not* sync:
- prompt history (`prompt-history.jsonl`)
- usage/frecency stats (`frecency.jsonl`)

If you already have local state on a machine and want to adopt the repo defaults:

#+begin_src sh
mv ~/.local/state/opencode/kv.json ~/.local/state/opencode/kv.json.bak
mv ~/.local/state/opencode/model.json ~/.local/state/opencode/model.json.bak
./script/bootstrap
#+end_src

If you want to explicitly sync your current (safe) local state back into the repo templates:

#+begin_src sh
./script/opencode sync push
#+end_src

* Oh My Zsh

This repo does *not* stow into =~/.oh-my-zsh= anymore.

- Keep =~/.oh-my-zsh= as a clean git checkout so =omz update= works.
- Put custom themes/plugins under =$ZSH_CUSTOM= (defaults to =~/.config/oh-my-zsh= in =zsh/.zshrc=).

Install Oh My Zsh (git clone):

#+begin_src sh
git clone https://github.com/ohmyzsh/ohmyzsh.git ~/.oh-my-zsh
#+end_src

Custom theme is shipped by this repo here:
- `oh-my-zsh-custom/.config/oh-my-zsh/themes/adrien-agnoster.zsh-theme`

* Local (per-machine) config

If you need machine-specific paths or secrets, put them in =~/.zshrc.local=.

Example template:
- `zsh/.zshrc.local.example`

* Migration note

If you previously overrode the theme inside =~/.oh-my-zsh=, remove that symlink so OMZ can update.

Typical fix:

#+begin_src sh
rm -f ~/.oh-my-zsh/themes/agnoster.zsh-theme
cd ~/.oh-my-zsh && git checkout -- themes/agnoster.zsh-theme
#+end_src
